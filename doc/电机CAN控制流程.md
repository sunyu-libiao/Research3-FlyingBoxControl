## 〇、完整控制流程（已实测跑通，电机会真的转）

上位机照这个顺序实现即可。所有帧都是 **11 位标准帧**，多字节字段 **小端**。

**协议里有两个地址字段，而且都被写成「设备号」**，这是本项目卡了很久的
「只有设备号 0 能生效」的真正原因，必须先分清：

| 字段                         | 由谁写进电机               | 决定什么                                                                        |
| ---------------------------- | -------------------------- | ------------------------------------------------------------------------------- |
| **设备号** `<dev>`   | `0x0313 Data[7]`         | 反馈与查询往哪儿回：`0x0380+dev` 心跳、`0x0408 Data[0]`、`0x0409 Data[0]` |
| **马达号** `<motor>` | `0x0316 Data[6]` bit3..0 | 运动帧听谁的：`0x0413/0x0414/0x0415/0x0416` 的 `Data[4]`                    |

两台电机挂在同一条总线上时，`<dev>` 和 `<motor>` 都必须互不相同。下文这两个占位符分开写，
不要再统一写成 `<dev>`。完整对照见「设备号 vs 马达号（2026-10-23 实测）」。

```
① 上电
   电机主动发 0x0312 [7 字节 SN]，例如 19 0C 03 07 96 2D 00

② 绑定 SN + 设备号
   TX  0x0313  <SN[0..6]> <dev>          无应答
   ★ 2026-10-19 干净状态实测：上电后 1.5s 一帧没有；走完 ②+③ 后
     0x0420/0x0440/0x0380 才开始上报。

③ 参数配置
   TX  0x0316  B4 BF CF AA 00 5F 00 <dev>
       Byte0=0xB4 极对数(4)  Byte1=0xBF 速度P/I  Byte2=0xCF 转矩P/I
       Byte3=0xAA 最大电流   Byte4=0x00 刹车/阻尼 Byte5=0x5F 速度D/转矩D
       Byte6 bit5/bit4 = 自动返回剩余位移/力矩，0 = 使能
       Byte6 bit3..0   = 马达号（决定运动帧听谁的，见「设备号 vs 马达号」）
       Byte7 = 设备号
  无应答；但发完之后 0x0420/0x0440 开始持续上报 —— 反馈开关在 Byte6，不在 0x0413。

④ 配置轮径 —— 【必需】，不做这一步运动指令不会执行
   TX  0x0408  <dev> 24 <轮径 u16 LE>     连发 3 次
       轮径单位 0.01mm（20mm → 2000 = D0 07）
   实测会回 0x0409（协议文档写的是「无应答」，实际有）
   ★ 注意：0x0100 [34 12] 不是缺轮径专属，配好轮径、正常运动时也会回（见下文）。

⑤ 上电使能 —— 只决定电机能否被驱动，不影响反馈流
   TX  0x0413  5A 00 00 00 <motor>
   RX  0x041A  13 04 <motor>               ACK，原始帧 ID 小端，末字节是马达号
   实测 0x0420 / 0x0440 / 0x0380 在 ③ 之后就已经持续上报（约 105 帧/秒），
   与 0x0413 使能/释放无关。
   （下电释放：0x0413 4A 00 00 00 <motor> —— 发完反馈流不会停，实测）

⑥ 设置运动参数（都是 u32 + 马达号，5 字节）
   TX  0x0414  <加速度 u32 LE> <motor>    单位 0.1 mm/s²   → 回 0x041A
   TX  0x0415  <速度   u32 LE> <motor>    单位 0.1 mm/s    → 回 0x041A

⑦ 下发目标位置（6 字节）
   TX  0x0416  <位移 s32 LE> <motor> <类型> 单位 0.1 mm    → 回 0x041A
       类型：0x00 相对（当前位置+Δ）/ 0x05 绝对（坐标系里的 P）/
             0x0A 归零 / 0x0B 把当前位置设成给定值（电机不动）
   ★ 重复发同一条：相对会继续走，绝对已在目标点就不动（见「相对 vs 绝对」实测）

⑧ 运行期间订阅反馈（实时曲线用周期帧；需要单点核对时也可主动查询）
   RX  0x420+motor  <剩余位移 s32 LE> <从通道 s32 LE>   ~50 Hz   帧 ID 跟马达号
   RX  0x440+motor  xx xx <力矩 s16 LE> xx xx xx xx     ~50 Hz   帧 ID 跟马达号
   RX  0x380+dev    ...                                 ~5 Hz    心跳，帧 ID 跟设备号
   RX  0x0409  查询应答：data[0:2] 回显 dev+子码，data[2:6] 为载荷
       0x08 → 当前位置 s32 LE（0.1mm），实测 +1.0mm 后回 10
       0x25 → 状态（data[2] 为状态位）
   RX  0x0100 [34 12]  每次非零相对运动目标都会出现，电机同时正常运动；
       不是缺轮径错误（相对 0 位移和 0x0B 不出现）
   RX  0x0102 / 0x0104 / 0x0105 / 0x0107 / 0x0108
                      <错误码 u16 LE> 未到位 / 堵转 / 超温 / 欠压 / 断线
   ★ 0x0420 是【到目标点的剩余量】不是绝对位置，减到 0 就是到位。
     相对命令后它从 Δ 递减；绝对命令后它是 P − 当前位置（可为负）。
     所以「实时角度」不能只看它：查 0x0408/0x08，或用 目标坐标 − 剩余值 还原。

⑨ 收尾
   TX  0x0413  4A 00 00 00 <dev>    下电释放
```

### 五个必须记住的坑

1. **周期反馈帧由 `0x0316` 参数开启，不是 `0x0413` 使能。** 2026-10-19 干净状态实测：
   上电后 1.5s 一帧没有；发完 `0x0316`（`Byte6` 的 bit5/bit4=0）后 `0x0420`/`0x0440`/
   `0x0380` 立即开始（约 105 帧/秒）；发 `0x0413 [4A]` 释放后流仍在继续。`0x0413` 只控制
   电机能否被驱动。调试时若「收不到反馈」，先确认 `0x0316` 的 `Byte6` 和绑定步骤。
2. **`0x0408/0x24` 配轮径不能省，但 `0x0100 [34 12]` 不能当成缺轮径错误。**
   实测配好轮径、正常运动时，每次非零相对目标（+20/-20/+10/-10 都试过）都会回
   `0x0100 [34 12]`，电机同时正常运动；相对 0 位移和 `0x0B` 设当前位置不产生该帧。
   它更像是「运动指令受理」标记，确切含义未确认，不要据此判失败。
   配轮径本身会回 `0x0409`（文档写「无应答」是错的）。
3. **`0x0408` 查询可以用，但必须先完成绑定 + 参数配置。** 实测 `[00 08]` 会回
   `0x0409 00 08 <位置 s32 LE> xx xx`：移动 +1.0mm 后回 `0A 00 00 00`（=10，1.0mm）；
   0 附近会在 `0` / `-1` 之间抖动（0.1mm 量化）；`[00 25]` 状态查询也有应答。
   之前判「无应答」，是准备步骤没做完。
4. **`0x0420` 是「到目标点的剩余位移」不是绝对位置。** 下指令后一路减到 0，减到 0 即到位；
   静止时报 0。相对命令时它从 Δ 递减；绝对命令时它是 `目标坐标 − 当前位置`（可为负）。
   所以「实时角度」不能只看剩余位移：要么查 `0x0408/0x08`，要么按目标坐标减剩余量还原。
5. **CANable 会缓存帧。** 上电那一下的 `0x0312` 可能几分钟后才吐出来，看着像刚发的
   指令的应答。脚本/上位机每次连接后都要先 flush 掉残留帧。

### 设备号 vs 马达号（2026-10-23 实测，影响所有运动帧）

协议 xlsx 里有两个互相独立的地址字段，却都写了「设备号」，而且文档自相矛盾：

- sheet1 第 19 行：`Data[6]：bit7=方向位 正反转 + 设备编号`
- sheet2「电机配置参数」：`Byte6` 的 `Bit3~Bit0 = 马达号`，`Byte7 = 设备号`
- 运动帧表（`0x0413/0x0414/0x0415/0x0416`）：`Data[4]：设备号`

**实测结论：`0x0316 Data[6]` 的 bit3..0 才是真正生效的那个「马达号」，运动帧 `Data[4]`
匹配的是它，不是设备号。** 协议表把运动帧的 `Data[4]` 写成「设备号」是错的——至少这颗固件
不是这么实现的，上位机必须迁就硬件实际行为。

| 协议原文          | 帧 / 字段                                                  | 实测实际含义                                    |
| ----------------- | ---------------------------------------------------------- | ----------------------------------------------- |
| 设备号            | `0x0313 Data[7]`                                         | **设备号**                                |
| 设备号            | `0x0316 Data[7]`                                         | **设备号**                                |
| 设备编号 / 马达号 | `0x0316 Data[6]` bit3..0                                 | **马达号** ← 运动帧的钥匙                |
| 设备号            | `0x0408 Data[0]`（查询 / 配轮径）                        | **设备号**（位置查询在设备号 2 上验证过） |
| 设备号            | `0x0413` `0x0414` `0x0415` `0x0416` 的 `Data[4]` | **马达号**                                |
| 设备号            | `0x041A Data[2]`                                         | **马达号**                                |
| `0x0420+设备号` | 帧 ID 低位                                                 | **马达号**                                |
| `0x0440+设备号` | 帧 ID 低位                                                 | **马达号**                                |
| `0x0380+设备号` | 帧 ID 低位                                                 | **设备号**                                |

测法：设备号固定为 2，只改 `0x0316 Data[6]` 的 bit3..0。

```
设备号=2 马达号=0   稳定后帧 ID：0x382 0x420 0x440
   0x0413 Data[4]=0 -> ACK 13 04 00      0x0414 Data[4]=0 -> ACK 14 04 00
   0x0415 Data[4]=0 -> ACK 15 04 00      0x0416 Data[4]=0 -> ACK 16 04 00
   使能/加速度/速度把 Data[4] 换成 1 或 2 -> 全部无 ACK

设备号=2 马达号=1   稳定后帧 ID：0x382 0x421 0x441
   0x0413 Data[4]=0 -> 无                0x0413 Data[4]=1 -> ACK 13 04 01
   0x0414 Data[4]=1 -> ACK 14 04 01      0x0415 Data[4]=1 -> ACK 15 04 01
   0x0416 Data[4]=1 -> 轮子走 +30（3.0mm）；ACK 偶尔抓不到，以位移为准
```

不只看 ACK，还用位置真值确认过：设备号 2、马达号 1 时，`Data[4]=0/2` 位移 +0，
`Data[4]=1` 位移 +30。所以不是「ACK 巧合」，是电机真的只认马达号。

三点必须注意：

1. **`0x041A Data[2]` 回的是马达号，不是设备号。** 上表设备号一直是 2，ACK 末字节却跟着
   马达号变成 `00` / `01`。所以**不能用 ACK 判断绑定是否生效**——要看 `0x0380+dev` 的心跳
   ID 有没有变成目标设备号。
2. **`0x0420` / `0x0440` 的帧 ID 跟马达号，不是设备号**；只有 `0x0380` 心跳跟设备号。
   按 `0x0420+dev` 订阅会在改了马达号之后收不到帧。
3. **运动帧是广播的，各电机只按马达号认领。** 两台电机的马达号必须不同，否则一条命令
   两台一起执行。

#### 这就是「只有设备号 0 能控制电机」的成因（已于 2026-10-23 修复）

**修复前**：本仓库固件把两台电机的马达号都写成 0（旧 `motor.h` 的 `MOTOR_MOTOR_NO = 0`），
而运动帧 `Data[4]` 发的是设备号：

```
左轮 设备号 0 马达号 0 ┐
右轮 设备号 1 马达号 0 ┘   但运动帧发的是 Data[4] = 设备号

  发 Data[4]=0  ->  两台马达号都是 0  ->  两台一起动   （「左右轮同时动」）
  发 Data[4]=1  ->  没有马达号 1      ->  两台都不动   （「右轮完全不响应」）
```

**修复内容**（两处，缺一不可）：

1. `0x0316` 的 `Byte6` bit3..0 按轮子填不同的值：`MOTOR_MOTOR_NO_LEFT = 0`、
   `MOTOR_MOTOR_NO_RIGHT = 1`（马达号只有 4 bit，0..15，同一条总线最多 16 台）；
2. 运动帧 `Data[4]` 改发马达号 `motorInfo[].motorNo`，不再发 `deviceId`
   —— 涉及 `Motor_SendEnable` / `SendAccel` / `SendSpeed` / `SendTarget` /
   `SendSetPosition` 五处。

接收侧同样要按编号分开，否则反馈会串到另一台：

| 帧                                        | 按哪个编号路由      |
| ----------------------------------------- | ------------------- |
| `0x0380+dev` 心跳                       | 设备号 `deviceId` |
| `0x0408` 查询 / 配轮径、`0x0409` 应答 | 设备号 `deviceId` |
| `0x041A` ACK 的 `Data[2]`             | 马达号 `motorNo`  |
| `0x0420+motor` 剩余位移                 | 马达号 `motorNo`  |

上位机/脚本排查时注意：`0x0316` **无应答**，所以马达号有没有真的写进电机，
只能靠行为判断——给不同轮子发不同的 `Data[4]`，看是哪一轮动。

复现这张表：`python test_device_id.py --sn <SN> --devices 0 1 2`
（仓库根目录，脚本会分别按「`Data[4]`=设备号」和「`Data[4]`=马达号」两种情况测过去）。

### 单位换算

| 量              | 协议单位   | 换算                  |
| --------------- | ---------- | --------------------- |
| 位移 / 剩余位移 | 0.1 mm     | `值 = mm × 10`     |
| 速度            | 0.1 mm/s   | `值 = mm/s × 10`   |
| 加速度          | 0.1 mm/s² | `值 = mm/s² × 10` |
| 轮径            | 0.01 mm    | `值 = mm × 100`    |
| 温度            | 0.1 °C    | `值 = °C × 10`    |

**位移 → 角度**：`deg = 位移(0.1mm) ÷ 10 ÷ (π × 轮径mm) × 360`。
例：轮径 20mm，一圈 = 628.3 单位；`628 单位 ≈ 359.8°`（协议单位是整数，只能逼近整圈）。

### 位移 = 轮缘滚过的弧长（不是电机转角）（2026-10-19 实测）

协议里的 **位移 / 剩余位移 / 速度 / 加速度** 都是**轮子外缘（节圆）上的长度量**：
位移 = 轮缘滚过的弧长 `s`（0.1mm 单位），也就是轮子贴着地面/齿条走出的直线距离，
不是电机轴转角、也不是编码器计数。轮径 `D` 只负责在「弧长」和「转角」之间换算：

```
s = πD × θ/360          θ_deg = s ÷ (πD) × 360
```

依据：

1. 协议表 `0x0408/0x24` 注释：`Data[2~3]：轮径（单位 0.01mm 对应 0.1mm 位移）`
   —— 轮径和位移用同一把长度尺，只是刻度差 10 倍。
2. 「电机配置参数」表：`轮径 0.01mm`、`位移 0.1mm`，备注
   **「两者相关，如果轮径放大或缩小 n 倍，则位移也需要放大或缩小 n 倍」** —— 正是 `s ∝ D`。
3. 实测：把轮径从 20mm 改成 40mm 后，同样下发 10 单位（1.0mm）相对命令，
   `0x0420` 剩余位移峰值仍是 9、`0x0408/0x08` 位置读数也仍是 0 → ≈10。
   即**位移读数是纯长度量、与轮径参数无关**；轮径只决定「同样的长度要转多少度」。

实用推论：

- **轮径配错 = 静默错误。** 配成 2 倍，同样的位移命令实际只转一半（或两倍），
  但位置读数、剩余位移、到位判断全部正常，总线上看不出异常。轮径必须是真实值
  （滚轮直径 / 齿轮节圆直径）。
- **速度、加速度同样是轮缘线速度/线加速度**（0.1mm/s、0.1mm/s²），
  「每秒多少度」要再除以 `πD`。

轮径 20mm：`628 单位 = 62.8mm = 1 圈`，`157 单位 ≈ 90°`，`10 单位（1.0mm）≈ 5.73°`。
自检：轮子上画个记号，配 20mm，发 `move --dist-mm 62.8 --yes`（628 单位），应正好转回原位。

### 相对位移 vs 绝对位移（2026-10-19 实测）

`0x0416` 的 `Data[0~3]` 是同一个 s32，但含义由 `Data[5]` 的目标类型决定：

| 目标类型      | `Data[0~3]` 含义     | 实际目标点    | 重复发同一条              |
| ------------- | ---------------------- | ------------- | ------------------------- |
| `0x00` 相对 | 相对当前点的增量 Δ    | 当前位置 + Δ | 会继续走（可累加）        |
| `0x05` 绝对 | 当前坐标系里的坐标值 P | P             | 已在 P 附近就不动（幂等） |

坐标零点由 `0x0B`（把当前位置设成给定值，电机不动）或 `0x0A`（回零点，电机会动）确定。
实测（`0B` 设原点 → 读数带 1 个单位量化偏差）：

```
设原点 0    → 位置读数 -1≈0
相对 +1.0   → 剩 9  → 位置 9        （0.9mm）
相对 +1.0   → 剩 9  → 位置 20       （2.0mm，累加）
相对 +1.0   → 剩 9  → 位置 29       （2.9mm，累加）

设原点 100  → 位置读数 99           （=9.9mm，坐标系被整体平移）
绝对 15     → 剩 -85 → 位置 36…14   （退 8.5mm 到 1.4mm 处，而不是“走 +1.5mm”）
绝对 15 再发→ 剩 0，电机不动         （幂等）
绝对 0      → 剩 -16 → 位置 -1≈0
```

- **绝对命令走的是「坐标差」**，方向由 P 与当前位置的大小关系决定：同一串数字用
  绝对和相对下发，行程可能完全不同。
- **到位有约 1~2 个单位（0.1~0.2mm）的死区**：目标 15 最终读到 14。不要为了
  「精确到位」反复补发，会一直在死区边缘来回。
- `0x0420` 是「到目标点的剩余量」：相对时等于还剩多少 Δ；绝对时等于 `P - 当前位置`，
  可能为负。显示绝对角度要用 `0x0408 [dev 0x08]`，或「目标坐标 − 剩余位移」还原。

脚本对应写法：`move --dist-mm 2`（默认相对）、`move --type abs --dist-mm 1`（绝对，
脚本会先查起始坐标，`--back` 时回到那个坐标而不是发 `-P`）。

陀螺仪项目建议：要「转到某个角度」用**绝对**（不累积误差，重复下发安全）；
但依赖稳定零点，上电后先 `0x0B`/`0x0A` 建一次原点。掉电后零点是否保留未实测。

| 设备号（设备编号）     | **由 `0x0313` 写入，不是固件固定值** | `0x0313` 的 `Data[7]` 写进去；绑成 2 之后 `0x0380+dev` 心跳 ID 变成 `0x382`。注意 `0x041A` 的 `data[2]` **不是**设备号，是马达号（见「设备号 vs 马达号」） |
| 多字节字段字节序       | **小端 LE**                            | ACK 里 `0x0413` 的低两字节排成 `13 04`，正是小端                                                                                                                         |
| 使能/释放              | **有应答**                             | `0x0413 [5A 00 00 00 00]` 稳定回 `0x041A`，重复发每次都回                                                                                                                |
| 周期反馈帧             | **`0x0316` 之后持续上报**            | 干净上电 1.5s 无帧 → 发 `0x0316` 后约 105 帧/秒；`0x0413 [4A]` 释放后仍在报                                                                                             |
| 配轮径                 | **必需，且会回 `0x0409`**            | 未配轮径时目标不执行（旧结论）；`0x0100 [34 12]` 正常运动时也会回，不能当缺轮径错误                                                                                        |
| `0x0408` 查询        | **可用（需先完成准备）**               | `[00 08]` → `0x0409 00 08 0A 00 00 00 xx xx`，位置=10=1.0mm；`[00 25]` 也回（`00` 是当时绑定的设备号）                                                              |
| **电机实际转动** | **✅ 已验证**                          | `move` 下 `0x0420` 出现行程并回到 0；C# `--motor-test` 下 `±5°`/`±30°` 也真实移动                                                                              |
| 位移的物理含义         | **轮缘弧长（长度量）**                 | 轮径 20→40mm 后同样的 10 单位命令，剩余位移峰值仍 9、位置读数仍 0→10                                                                                                       |
| 速度 / 加速度含义      | **轮缘线速度 / 线加速度**              | 同上；转角要除以 `πD`                                                                                                                                                     |

### `query-hunt` 的 `[FF 00]` “命中”是假线索（只否定反序查询）

> 这一节只针对反序写法 `[子码, 设备号] = [FF 00]`。文档顺序 `[设备号, 子码] = [00 08]`
> 后来复测是有效的，见下一节。（这里的 `00` 是当时绑定的设备号；换成别的设备号时，
> 第一个字节跟着变。）

```
17:40:26  TX 0x408 [FF 00]  ->  RX 0x409 FF 00 00 00 FF 5F 62 00
17:46:25  TX 0x408 [FF 00]  ->  RX 0x409 FF 00 00 00 00 77 7E 00
```

我一度以为"字节序文档写反了、`0xFF` 能查版本"。把两次采样逐字节差分后推翻了这个判断：
只有 `data[4..6]` 在变，`data[5:7]` 按小端读是 `25183 -> 32375`（Δ=7192），而两次采样
实际相隔约 345~350 s，即**每秒约 20.5 次单调递增**。

电机此刻是静止的，位置不可能稳定增长，所以这个字段是**内部计数器**（约 20 Hz tick，
多半是开机时长/调度计数），不是版本号、不是位置、不是温度。因此：

- 前两个字节只是把请求原样回显，从应答里推不出"谁是设备号"，用它反推字节序不成立
  （我先前"文档写反了"的推论作废）；
- 这只说明 `[FF 00]` 这个反序变体没有可用的版本/位置信息；文档顺序 `[00 08]` 的位置查询
  是有效的（见下节）。

### 结论：实时曲线读周期帧，位置可用 `0x0408` 查询核对

上位机实时曲线应该**订阅** `0x0420+dev`（剩余位移 s32，0.1mm）与 `0x0440+dev`（力矩 s16）；
需要单点核对当前位置/状态时，再发 `0x0408 [dev, 0x08/0x25]` 读 `0x0409`。2026-10-19 实测：

```
TX 0x0408 [00 08]  ->  RX 0x0409 [00 08 0A 00 00 00 99 FF]   # +1.0mm → 10
TX 0x0408 [00 08]  ->  RX 0x0409 [00 08 00 00 00 00 88 FF]   # 回零   → 0
TX 0x0408 [00 08]  ->  RX 0x0409 [00 08 FF FF FF FF 89 FF]   # 0 附近 → -1（量化抖动）
TX 0x0408 [00 25]  ->  RX 0x0409 [00 25 03 AA C2 FF FF FF]   # 状态位 = 0x03
```

注意 `0x0409` 的 `data[0:2]` 是请求回显，`data[2:6]` 才是载荷（位置 s32 LE）；
`data[6:8]` 两次采样分别是 `99 FF` / `88 FF` / `89 FF`，含义未确认，先不要用。
查询是低速的，且 CANable 有缓存，读之前先 flush，必要时隔 100ms 再读一次；
0 附近读到 `0` 或 `-1` 是 0.1mm 量化抖动，不是设置失败。

**轮询频率**：上位机在完成 ② 参数配置后按 **10 Hz**（100 ms）自动查询位置，
负载约 320 B/s（10 帧查询 + 10 帧应答），相比既有 ~105 帧/秒的反馈流只多约 3%，
115200 的 slcan 串口和 1 Mbps CAN 都远未饱和；上限受 `REFRESH_MS = 33`（30 Hz UI 刷新）约束。
"读当前位置"按钮可用于未配置参数时的单次查询或排障（看状态行"回读 N 帧"是否增长）。
另外 `0x0420` 是**到目标点的剩余量**（减到 0 即到位），不是位置本身：相对命令时可用
「上一次位置 + (Δ − 剩余)」插值，绝对命令时用「P − 剩余」还原
（见「〇」的第 8 条与第 4 个坑）。

要批量核对其它子码时仍可用：`matrix`（设备号×子码×顺序×DLC 全组合扫描，命中自动复测
3 次以排除缓存重播）、`watch`（密集采样同一查询，逐字段差分算速率，用来区分常量/计数器/
实时量）、`sub-scan`（256 个子码全扫）。

### 两个必须知道的坑

**CANable 会在内部 RAM 缓存 CAN 帧。** 电机上电瞬间那一条 `0x0312`，可能在几分钟后
才被吐出来，看起来像是"刚才那条指令的应答"——**这是假阳性**。

我第一轮测试就被它骗过一次：`0x0313` 绑定后"收到" `0x0312`，实际是缓存里的旧帧
（后续单独复测 `0x0313` 无任何应答，证明它只是重播）。脚本现在每次连接后自动
`flush()` 丢弃缓存帧，日志里会打印"已丢弃适配器缓存里的 N 帧陈旧数据"。

**同一个坑还骗过我第二次**：`params` 之后看到反馈帧涌现，我一度怀疑那是缓存残留，后来又
误判成"`0x0413` 使能才是上报开关"。2026-10-19 干净状态复测：上电后 1.5s 无帧；发 `0x0316`
后 `0x0420`/`0x0440` 立即开始；发 `0x0413 [4A]` 释放后仍持续上报。结论：上报开关是
`0x0316` 的 `Byte6` bit5/bit4（0=使能），`0x0413` 只控制电机能否被驱动。
凡是"发了一条指令就看到帧"这种推断，都必须在干净状态下单独复测一次才能采信。

### SN

抓包图里的 `0x0312` 数据 = `19 0C 03 07 96 2D 00`（7 字节），已设为脚本与上位机的默认值。

### 上电判左右（固件行为，2026-10-26 起）

电机**不保留** `0x0313` 的绑定和 `0x0316` 的方向位，断电再上电就回到空白；而 SN
本身不含左右信息，两条 `0x0312` 的到达顺序也没有意义。固件因此把"身份"和"侧别"分开：

```
① 上电收集 0x0312，最多两条，按到达顺序记为 slot 0 / slot 1
② 0x0313 绑定（slot 0 → 设备号 0，slot 1 → 设备号 1）
③ 0x0316 配置：bit7 按槽固定，slot 0 = 0，slot 1 = 1；马达号 0 / 1
④ 0x0408 轮径 ×3 → 0x0416 类型 0x0B 置零 → 0x0413 使能
⑤ 等陀螺仪零偏标定结束（推车会污染标定，所以必须排在它之后）
⑥ 提示推车：LED 快闪 = 扶稳别动（采基线），慢闪 = 朝车头推一下，常速 = 完成
⑦ 判据：两轮 0x0440 扭矩相对基线的变化**同号**
     同号且等于 MOTOR_SIDE_FORWARD_SIGN → slot 0 就是左轮，结束
     同号但符号相反               → 两条 SN 对调后重新绑定 + 配置 + 置零
     一正一负 / 低于死区          → 推歪了或信号不足，重试
```

要点：

- **看扭矩不看位移**：电机已使能并锁住位置，推车时轮子几乎不转，扭矩会升高，所以
  车不用真的移动。
- **扭矩帧跟马达号**：`0x0440 + 马达号`，`Data[2..3]` 为 s16，协议没给单位，固件只用符号。
- **必须同号**：只有一颗轮子受力（抬起、打滑、斜推）会被拒绝，不会被当成有效推车。
- **重绑而不是翻方向位**：运动与里程计代码把 slot 0 当左轮，所以左轮必须真的落在 slot 0；
  翻 bit7 只会让"前进"变正，却会让 yaw 公式反号。
- **没有 SN 上报时不推车**：只复位 MCU、电机没断电时电机仍保留绑定，固件直接用
  编译期的 `MOTOR_SN_LEFT/RIGHT` 兜底，跳过判左右。
- **扭矩符号与位移符号相反**：轮子被往前推、位置计数变大时，`0x0440` 读到的是负值。
  所以 `MOTOR_SIDE_FORWARD_SIGN` 填 `-1`（若填成 `+1`，每次上电都会误判成绑反而多对调
  一次）。判据只比较两轮是否同号、以及是否等于这个常量，换电机型号后重新确认这一个宏即可。
- 推车失败（没推、推歪、信号太小）会重试 `MOTOR_SIDE_ATTEMPTS` 次；仍失败则跳过 demo
  路径并报码 3——方向未知时继续跑 5 m 直行可能直接撞墙。

#### 运动模式（宏切换，`motor.h`）

上电流程走完后，电机任务按 `MOTOR_DEMO_MODE` 跑选定的路径，重复 `MOTOR_DEMO_REPEAT` 次：

| 宏                                     | 默认                   | 含义                                                    |
| -------------------------------------- | ---------------------- | ------------------------------------------------------- |
| `MOTOR_DEMO_MODE`                    | 见下方当前值           | 选中的路径，见下表                                      |
| `MOTOR_DEMO_REPEAT`                  | 见下方当前值           | 整套路径重复次数                                        |
| `MOTOR_DEMO_STRAIGHT_LEG`            | `50000`              | 直线段长度，0.1 mm = **5 m**                      |
| `MOTOR_DEMO_SQUARE_SIDE`             | `10000`              | 正方形边长，0.1 mm = **1 m**                      |
| `MOTOR_DEMO_SQUARE_TURN`             | `90000`              | 拐角角度，0.001 deg = **90°**（顺时针）          |
| `MOTOR_DEMO_CALIBRATE_DISTANCE`      | `50000`              | 标定模式的直行距离，0.1 mm = **5 m**（负数=后退） |
| `MOTOR_DEMO_SPIN_DIRECTION`          | `+1`                 | 旋转模式方向：`+1` 顺时针 / `-1` 逆时针             |
| `MOTOR_DEMO_SPEED` / `_ACCEL`      | `4000` / `8000`    | **400 mm/s**，0.8 m/s²（0.5 s 斜坡）             |
| `MOTOR_DEMO_TURN_SPEED` / `_ACCEL` | `90000` / `180000` | **90 °/s**（= 304 mm/s 轮缘），180 °/s²        |

> **角速度不等于轮缘速度。** 底盘转速换算到单轮要多乘 `π × 轨距 / 360 ≈ 3.38`：
> `轮缘 mm/s = 角速度[°/s] × π × 387 / 360`。所以 90 °/s 对应 304 mm/s 轮缘，
> 只占直行 400 mm/s 的 76%。
> **转弯的可提速上限 = 直行轮缘速度**：400 mm/s 时最多约 **118 °/s**。超过这个值就是让
> 转弯要求驱动比直行还快，会跑不完、超时停车（码 4）——135 °/s 就是这么失败的。
> 改这两个宏时务必用上面的公式核对。

四种模式：

| 模式                              | 一次重复的动作                                                          | 耗时（400 mm/s，转弯 90 °/s） |
| --------------------------------- | ----------------------------------------------------------------------- | ------------------------------ |
| `MOTOR_DEMO_MODE_STRAIGHT_BACK` | 前进 5 m → 掉头 180° → 前进 5 m（回到起点）→ 掉头 180°（车头复原） | 约 31 秒                       |
| `MOTOR_DEMO_MODE_SQUARE`        | 前进 1 m → 顺时针转 90°，共 4 次（回到起点、车头复原）                | 约 18 秒                       |
| `MOTOR_DEMO_MODE_CALIBRATE`     | 直行 `MOTOR_DEMO_CALIBRATE_DISTANCE` 后**停在原地**，不转弯     | 5 m 约 13 秒                   |
| `MOTOR_DEMO_MODE_SPIN`          | 原地转整 `360° × MOTOR_DEMO_SPIN_DIRECTION`，不移动                 | 1 圈约 6 秒                    |

`MOTOR_DEMO_SPEED` 等是**真实速度**：`MOTOR_MOTION_SCALE_NUM/DEN`（29320/10000）在
`Motor_RunWheels()` 里统一施加，位移、速度、加速度都乘同一个倍数，所以宏写多少就是
车实际走多少。想让车更快只改 `MOTOR_DEMO_SPEED`，加速同比例调（保持 `SPEED/ACCEL` 不变，
加减速时间就不变）。太快会打滑，表现为跑完位姿对不上（码 8）。

**换速度后先验证不打滑**：用 `MOTOR_DEMO_MODE_CALIBRATE` 跑一段固定距离，量实际值。

- 和旧速度下量到的一样 → 没有打滑，可以放心用
- 明显变短 → 打滑了，退回上一档

截止时间不用管：`Motor_MoveTimeoutMs()` 按 `距离/速度` 现算，改速度后自动跟着变。

前两种模式每一圈都是闭合回路，所以重复 N 次后仍然回到起点；最后用
`MOTOR_DEMO_RETURN_TOLERANCE`（50 mm）检查位姿是否回到原点，超出则报码 8。
标定模式故意停在别处，**跳过位姿检查**。

#### LED 失败码

跑完（或中途放弃）后 LED 不再只是"快闪"，而是**闪 N 次 + 停顿 1.2 秒，循环**，
N 就是失败环节。成功时是原来的 1 Hz 心跳（不闪码）。

| 闪几下         | 宏                              | 含义                                               |
| -------------- | ------------------------------- | -------------------------------------------------- |
| 心跳（不计数） | `MOTOR_FAIL_NONE` = 0         | 全部成功                                           |
| 1              | `MOTOR_FAIL_INIT`             | 初始化失败：有电机没走完 0x0313/0x0316/0x0408/使能 |
| 2              | `MOTOR_FAIL_GYRO`             | 陀螺仪角度始终不可用（其余动作都正常）             |
| 3              | `MOTOR_FAIL_SIDE`             | 推车判左右失败（没推、推歪、信号不足）             |
| 4              | `MOTOR_FAIL_MOVE_TIMEOUT`     | 某段运动撞到截止时间                               |
| 5              | `MOTOR_FAIL_MOVE_STALL`       | 某轮连续 4×200 ms 没动 → 判卡死                  |
| 6              | `MOTOR_FAIL_MOVE_NO_POSITION` | 起步前拿不到新鲜位置应答                           |
| 7              | `MOTOR_FAIL_MOVE_ENABLE`      | 有轮子没使能，整段拒绝下发                         |
| 8              | `MOTOR_FAIL_LOOP`             | 位姿闭合检查失败（走完但没回到原点）               |

判读规则：

- **2 只在"其他都没错"时才出现**：陀螺坏不阻止运动，所以如果同时还有运动失败，
  报的是运动那个码（更可操作）。
- 计数起点：`t=0` 第一次点亮，闪间隔 150 ms 亮 / 250 ms 暗，一组结束停顿 1.2 s。
  闪 8 下的一组约 4.4 s，节奏很慢，用手机录像数最省事。
- 也可以直接读 `Motor_GetFailCode()`（同一份值）。

怎么排查：

| 码 | 先查什么                                                                                |
| -- | --------------------------------------------------------------------------------------- |
| 1  | 电机是否上电、CAN 线、`motorInfo[i].failedStep`（1=绑定 2=配置 3=轮径 4=置零 5=使能） |
| 2  | 车在陀螺标定期间被碰过？`XV7001bb_IsAngleUsable()`                                    |
| 3  | 慢闪时有没有推、是不是朝车头方向、力度够不够                                            |
| 4  | 速度是否被调得太低、地面是否打滑、`MOTOR_MOVE_TIMEOUT_MARGIN_PCT`                     |
| 5  | 该轮是否顶住东西、堵转、编码器断线                                                      |
| 6  | 里程计任务是否在跑、云台/CAN 是否丢帧（`MOTOR_POSITION_TIMEOUT_MS`）                  |
| 7  | 初始化是否真的使能成功（码 1 的细分）                                                   |
| 8  | 打滑，或 `MOTOR_MOTION_SCALE` / `MOTOR_TRACK_001MM` 标定不准                        |

切换方式（二选一）：

```c
/* motor.h 里改默认值 */
#define MOTOR_DEMO_MODE     MOTOR_DEMO_MODE_SQUARE
```

```
:: 或者命令行覆盖，两个宏都支持 -D
-DMOTOR_DEMO_MODE=MOTOR_DEMO_MODE_SQUARE -DMOTOR_DEMO_REPEAT=3
```

#### 标定轴距（`MOTOR_DEMO_MODE_SPIN`）

`MOTOR_TRACK_001MM`（几何轮心距实测 388 mm，当前生效值 **384.96 mm**）在转弯时会因为
轮胎横向刮擦而偏离几何值，真实"有效轴距"通常小 1~3%，**卷尺量不出来**。用陀螺或地面
参照反算才准。

不要指望一次算准，**按迭代做**：跑一遍 → 量两线夹角 R → 乘系数 → 再跑一遍，直到 R < 1°。

**前提：先标好倍数**，否则倍数误差会被轴距一起吸收 —— 同一个 10° 的旋转偏差，倍数没
标准时算出来是 385.86 mm，倍数标准后是 387.14 mm，差了 1.3 mm。顺序反了会标错。

**倍数一旦改了，轴距必须跟着改**。转角命令的换算链是

```
角度 → Motor_RotationTravel()（÷ 轴距, 得真实轮行程）→ × MOTOR_MOTION_SCALE → 协议单位
```

所以车实际转过的角度与 `MOTOR_TRACK_001MM × MOTOR_MOTION_SCALE` 成正比，两者必须成反比
调整，**乘积保持不变**：

| 时间       | 倍数              | 轴距              | 乘积        |
| ---------- | ----------------- | ----------------- | ----------- |
| 2026-10-26 | 2.9203（`29203`） | 386.50（`38650`） | 1128.70     |
| 2026-10-27 | 2.9320（`29320`） | **384.96（`38496`）** | 1128.70 |

只改倍数不改轴距，每条旋转命令会**长 0.40%**，180° 掉头多转 0.72°，方形四个角累积 2.9°。
只改轴距不改倍数同理反向。改完两者都要跑一遍 `test_motion.ps1`。

> 闭环旋转在陀螺上，轴距只决定第一轮下发多远，所以轴距差 0.4% 对最终角度影响很小
> （仿真 179.810° → 179.831°，差 0.02°）。真正受影响的是**陀螺不可用时的开环回退**
> 和里程计里由轮子推算的偏航角，那里误差是全额 0.4%。

```
① 平整硬地面，留 1 m × 1 m 空间，车顶贴一根 ≥500 mm 的指示杆
② 车放好，沿指示杆方向在地上画一条延长线
③ motor.h：MOTOR_DEMO_MODE     = MOTOR_DEMO_MODE_SPIN
           MOTOR_DEMO_REPEAT    = 5              (= 5 整圈 = 1800°)
           MOTOR_DEMO_SPIN_DIRECTION = +1（顺时针）
④ 上电跑完（约 45 秒），车转 5 圈回到起点
⑤ 再沿指示杆画一条线，量两条线的夹角 R
⑥ 新轴距 = 当前轴距 × 1800 / (1800 + R)
          例（当前 384.96）：多转 3°（R=+3）→ 384.96 × 1800/1803 = 384.32
              少转 3°（R=-3）→ 384.96 × 1800/1797 = 385.60
⑦ MOTOR_TRACK_001MM 填新值（0.01 mm 单位）
⑧ 复测：再跑 5 圈，两线夹角应 < 1°（相当于轴距误差 < 0.11%）
```

**实测记录（2026-10-26）**（其中的倍数已于 2026-10-27 复标为 2.9320，见「标定倍数」）：

| 步骤                               | 值                                                                   |
| ---------------------------------- | -------------------------------------------------------------------- |
| 直行 1500 mm 实测                  | 1505 mm（多 0.333%）                                                 |
| 倍数修正                           | 2.93 × 1500/1505 = **2.9203** → `29203/10000`              |
| 第 1 次旋转（轴距 388，旧倍数）    | 5 圈多转 10°                                                        |
| 第 1 次推理出的轴距                | 388 × 1800 × (1505/1500) / 1810 = **387.14 mm** → `38714` |
| 第 2 次旋转（轴距 387.14，新倍数） | 5 圈多转 3°（实测 1803°）                                          |
| **第 2 次修正轴距**          | 387.14 × 1800/1803 = **386.50 mm** → `38650`               |

这是**迭代收敛**的过程：每次跑一遍、量一次、乘一次系数。到 386.50 时，两次测量的
不一致（387.14 与 386.50）已经等于 3°/5 圈，和量角读数误差同量级，再迭代只是在追读数噪声。

**方法的分辨率上限**：两条线读到 ±1°，对应轴距 ±0.43 mm（= 0.11%），换回旋转换算
就是 **±0.9°/5 圈**。想再准只能上闭环（用陀螺做转角反馈），继续调常量没有意义。

要点：

- **必须 5 圈以上**：1 圈只放大到 3.6°，量角误差占比太大。
- **两个方向都测**（`SPIN_DIRECTION` 改 `-1`），结果应一致；不一致说明有系统性侧滑。
- 每次转一整圈、单独下发（不是一次 5 圈的大位移），每圈都有到位检查。
- 这只是纯旋转，**没有平移，不受直行打滑影响**，量的是单纯的轴距误差。
- 改完这个常量，`MOTOR_ROTATION_SCALE_NUM` 和里程计的 `MOTOR_ODOM_YAW_NUM/DEN`
  都从它派生，一处改完全局生效。

#### 标定倍数（`MOTOR_DEMO_MODE_CALIBRATE`）

```
① 地面标出起点和 5 m 终点（卷尺，越远越准）
② motor.h：MOTOR_DEMO_MODE = MOTOR_DEMO_MODE_CALIBRATE
          MOTOR_DEMO_CALIBRATE_DISTANCE = 50000   (= 5 m)
③ 上电、推一下判左右、车直行 5 m 后停在原地
④ 量出实际走了 D 米
⑤ 新倍数 = 当前倍数 × 命令距离 / 实测距离
          例：命令 5 m 只走了 4.98 m → 2.9320 × 5000/4980 = 2.9438（倍数要变大）
              走了 5.02 m           → 2.9320 × 5000/5020 = 2.9203（倍数要变小）
⑥ 把新倍数写成 NUM/DEN（4 位有效数字），例如 2.9320 → 29320/10000
⑦ 重复 ②~⑤ 验证：第二次偏差应在 1~2 mm 内
```

要点：

- **只测直行**：转弯不参与，轮距误差不会混进来。倍数定准之后才有资格谈轮距。
- **`-DMOTOR_DEMO_CALIBRATE_DISTANCE=-50000`** 可以测后退，两个方向结果应一致；
  不一致说明有系统性侧滑或标定路线不平。
- **基准越长越准**：1 协议单位 ≈ 0.034 mm，量化不是瓶颈；瓶颈是卷尺读数。
  1.5 m 上 5 mm 的读数误差就是整个修正量，5 m 上同样 5 mm 只占 0.1%。
- 起点/终点最好在同一条直线上贴着地面标记，用车身固定参照点量。
- 精度：现在分母 10000，倍数分辨率 **0.0034%**，5 m 上是 0.17 mm，远超卷尺精度，
  所以测量误差是瓶颈，不是代码。

**倍数复标（2026-10-27）**

| 项   | 值                                                  |
| ---- | --------------------------------------------------- |
| 命令 | 5000 mm（`MOTOR_DEMO_CALIBRATE_DISTANCE = 50000`） |
| 实测 | 4980 mm（少 0.40%）                                 |
| 修正 | 2.9203 × 5000/4980 = **2.9320** → `29320/10000` |

两次标定的方向相反：1.5 m 时多走 0.333%（倍数调小），5 m 时少走 0.40%（倍数调大），
合计相差 0.73%，中间没有换过轮子或电机。1.5 m 上 5 mm 的读数差本身就占 0.33%，两次的
差异落在卷尺读数误差以内——所以 2.9320 不代表「2.9203 错了」，只说明 5 m 是更长的基准，
新值更可信。想真正定住它，同一段连续跑 3 次取平均，或用地贴固定标点代替卷尺两端对齐。

注意倍数只改变「命令的距离是否名副其实」，**不影响回到原点的精度**：每段下发的都是
绝对位置目标，往返的 `+T` 与 `-T` 严格相消，倍数误差只是整体缩放。

#### 倍数精度（为什么是 4 位有效数字）

`MOTOR_MOTION_SCALE_NUM/DEN = 29320/10000`，分辨率是 `1/29320 = 0.0034%`。

| 写法                    | 分辨率  | 1.5 m 直线 | 一圈 1 m 正方形（航向） |
| ----------------------- | ------- | ---------- | ----------------------- |
| `293/100`（2 位小数） | 0.34%   | ±5.1 mm   | ±0.61°                |
| `29320/10000`（现在） | 0.0034% | ±0.05 mm  | ±0.006°               |

倍数误差会**稳定累积**：航向误差 = 3.6° × ε × 圈数，所以 2 位小数的 0.17% 跑 5 圈
就是 3°。打滑至少方向随机，取整误差不是，所以要先把取整误差消掉。

另外 `Motor_RunWheels()` 的缩放是**四舍五入**，不是截断：0.1 mm 的命令精确值是 2.92
协议单位，截断会变成 2（短 31%），四舍五入是 3（短 2.7%）。短距离标定、微调都靠这个。

`MOTOR_DEMO_MODE` 填了别的值会直接 `#error`，不会静默跑错路径。

注意：

- 单段运动有**两个**独立的时间约束，别混为一谈：| 约束                                                                                      | 位置                                                               | 作用       | 触发后      |
  | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------ | ---------- | ----------- |
  | **截止时间**                                                                        | `MOTOR_MOVE_TIMEOUT_MARGIN_PCT`（现在 **200%**）           | 兜底       | 停车 + 失败 |
  | **进度看门狗**                                                                      | `MOTOR_RESEND_INTERVAL_MS` 200 ms × `MOTOR_RESEND_LIMIT` 3 次 | 真正判卡死 | 停车 + 失败 |
  | 5 m 段截止 = (16.7 + 0.5) × 3 = **51.5 s**，180° 转弯 = **7.5 s**，都远小于 |                                                                    |            |             |
  | `MOTOR_MOVE_TIMEOUT_MAX_MS`（120 s）。截止时间只是兜底，放大它不会让健康的运动失败。    |                                                                    |            |             |
- **看门狗按轮独立计数，并在该轮恢复位移时清零**。这一点很关键：早期版本用一个全车
  共享的 `resends` 累计计数，5 m 长段里只要有 4 次超过 200 ms 的短暂停（起步延迟、驱动
  饱和、接近目标时蠕动）就会在跑了一半时误判失败——实测在 8.2 s / 43% 处停车。
  现在只有“某一轮连续 4×200 ms 完全不动”才会失败，约 1 秒内报出。
- 方向位在 `MOTOR_SIDE_FORWARD_SIGN` 判对之前不要开跑：左右判错时直行会朝车尾走。

#### 轻推就能判（力的门槛）

扭矩 ≈ 刚度 × 位移：轻推时轮子几乎不动，扭矩本来就小，再叠加原始信号的噪声，
以前需要推得比较重才能过阈值。现在做三件事把门槛压下来，**不需要用大力**：

1. **低通滤波**：每个采样走一阶低通（`y += (x-y)/4`，约 40 ms），噪声按 √N 下降。
2. **两轮取平均**：判据用 `(左 + 右) / 2`，再降 √2；单轮略弱不再拖死判定。
3. **死区按滤波后的噪声算**：以前用原始信号的**峰峰值 ×4**，一个毛刺就能把阈值放大几倍；
   现在只统计滤波后、且跳过前 200 ms 预热段的峰峰值。

调参顺序（只有这三个）：

| 现象         | 改动                                                                                     |
| ------------ | ---------------------------------------------------------------------------------------- |
| 还是要用力   | 先降 `MOTOR_SIDE_MIN_DEADBAND`（20 → 10），再降 `MOTOR_SIDE_NOISE_FACTOR`（4 → 3） |
| 没推也判成功 | 反过来升 `MOTOR_SIDE_MIN_DEADBAND` 或 `MOTOR_SIDE_NOISE_FACTOR`                      |
| 推了但判不出 | 加大 `MOTOR_SIDE_PUSH_MS`（8 s → 15 s）或 `MOTOR_SIDE_HOLD_MS`                      |

死区单位是 `0x0440` 原始计数。想用实测值定它，可以让上位机订阅 `0x0440`：
静止时读到的峰峰值记为 N，推力刚好能过阈值时读到的变化记为 P，取 `N × 2 < 死区 < P`。

## 二、复现命令（流程已全部验证通过）

设备号由 `0x0313` 绑定写入（下面的命令按实测时的 `0` 填），电机已确认能实际转动。日常用这几条：

```powershell
# 动一下电机（内含 绑定+参数+配轮径+使能 全套准备，并自动回位、释放）
python tools\motor_probe.py move --dist-mm 2 --speed-mm-s 5 --accel-mm-s2 20 --wheel-mm 20 --yes --back

# 绝对定位：走到坐标系里的 1.0mm 处，再回到起始坐标（脚本会先查位置）
python tools\motor_probe.py move --type abs --dist-mm 1 --speed-mm-s 5 --accel-mm-s2 20 --yes --back

# 打开/确认反馈流（0x0316 参数之后就会上报；使能只影响能否运动）
# 刚上电且未绑定时，先按 ①~③ 绑定 + 参数，或直接跑上面的 move
python tools\motor_probe.py params --dev 0
python tools\motor_probe.py listen -t 10

# 收尾释放
python tools\motor_probe.py release
```

上位机（C#）界面把上面 ①~④ 做成了独立按键，每步旁边就是它的参数：

| 按键                | 报文                                            | 参数输入                                                                                                                           |
| ------------------- | ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 一键初始化 ①②③   | `0x0313` → `0x0316` → `0x0408/0x24` ×3 | 复用下面三步的全部输入                                                                                                             |
| 绑定 SN + 设备号    | `0x0313`                                      | 设备号、SN（7 字节 hex）                                                                                                           |
| 参数配置            | `0x0316`                                      | Byte0~Byte6（7 个 hex 框，旁边实时显示完整 8 字节预览，Byte7 自动填设备号）。**Byte6 的 bit3..0 = 马达号，两台电机必须不同** |
| 配置轮径            | `0x0408/0x24` ×3                             | 轮径（mm，旁边显示角度换算）                                                                                                       |
| 上电使能 / 掉电释放 | `0x0413` `[5A]` / `[4A]`                  | **马达号**（不是设备号，见「设备号 vs 马达号」）                                                                             |

运动控制面板（⑥⑦ 的按键化，速度/加速度/位移同时支持 mm 与 °）：

| 按键                        | 报文                                                     | 参数输入（mm ⇄ ° 双向联动）                    |
| --------------------------- | -------------------------------------------------------- | ------------------------------------------------ |
| 下发运动参数                | `0x0414` 加速度 + `0x0415` 速度                      | 速度（mm/s 或 °/s）、加速度（mm/s² 或 °/s²） |
| 相对运动                    | `0x0416` 类型 `0x00`                                 | 相对位移（mm 或 °）                             |
| 绝对运动                    | `0x0416` 类型 `0x05`                                 | 绝对位移 P（mm 或 °）                           |
| 停止                        | `0x0416` 类型 `0x00`，位移 0                         | 无（目标 = 当前位置）                            |
| 把当前位置设为上面的 P 0x0B | `0x0416` 类型 `0x0B`                                 | 复用绝对位移输入                                 |
| 往复运动（去 → 回零）      | `0x0414`+`0x0415`，然后 `0x0416` 类型 `0x05` ×2 | 角度（°）、速度（°/s）、加速度（°/s²）、次数 |
| 读当前位置 0x0408/0x08      | `0x0408` `[dev, 0x08]`                               | 无                                               |

单位联动都走协议单位换算（`mm → 0.1mm 单位 → °`），改轮径后按新轮径立刻重算；
任一框输入非数字、速度 0、超限（1000 mm/s、10000 mm/s²、10000 mm）都会拒绝下发。
运动类按键要求 ③ 已配轮径且 ④ 已使能，否则置灰并在运动状态行红字说明原因。

「一键初始化」用当前输入框里的设备号 / SN / 7 字节参数 / 轮径，把 ①→②→③ 一次发完，
结束时轮径已配置；它**不会**使能电机，使能仍需单独按 ④。三项输入会先整体校验，
任一项非法（SN 不是 7 字节、参数不是 hex、轮径 ≤ 0）则整组帧一帧都不发，
避免只配了 SN 就停在中途。

状态行会显示 SN 是否已绑定、参数/轮径是否已配置、当前是使能还是释放，以及 ACK、周期帧、
剩余位移、力矩。电机不回报「配置是否成功」，所以前三步只能按「发过没发过」记。

### 往复运动（E 行）

运动控制面板最下面一行是 E 往复运动，参数全部按**角度**给（内部按当前轮径换算成协议单位）：

| 输入             | 范围                              | 说明                                   |
| ---------------- | --------------------------------- | -------------------------------------- |
| 往复角度         | 非 0，`\|角度\| ≤ 3600`（10 圈） | 先绝对定位到 +这个角度，再绝对定位回 0 |
| 速度（°/s）     | `0 < v ≤ 5000`                 | 只对这组往复生效，会盖掉 A 行的速度    |
| 加速度（°/s²） | `0 < a ≤ 50000`                | 同上，会盖掉 A 行的加速度              |
| 次数             | `0 ~ 100000`，`0` = 一直往复  | 一次 = 出去 + 回到 0                   |

点「往复运动（去 → 回零）」后：先下发 `0x0414`/`0x0415`（用 E 行自己的速度/加速度），
再 `0x0416` 类型 `0x05` 绝对定位到 `+角度`。

**到位判定**（去程和回程都用同一套）：位置回读落在目标 `±tol` 内，且（收到过 `0x0420` 时）
剩余位移归零；`tol = max(2 单位, |行程| / 20)`，即 5% 且至少 0.2 mm 等价值。
`0x0420` 那一条是为了不让「刚好路过目标点」被误判成到位。

**两个防误判的保险**：

- 每个阶段至少要多收到 1 帧位置回读才判断，否则会拿指令发出**前**的旧位置直接判成到位。
- 长行程（单段预计耗时 ≥ 0.3 s）必须先看到「真的动了」（剩余位移 ≠ 0 或位置跟起点不同），
  否则电机没动（没使能、指令被拒）时会被瞬间判成到位、白跑 N 次。

**超时**：`max(5 s, 单段预计耗时 × 3 + 2 s)`，单段预计耗时 = `|行程单位| / 速度单位 + 速度单位 / 加速度单位`
（位移与速度单位同为 0.1 mm 系列，直接相除就是秒）。超时或指令发送失败会退出等待并在状态行红字说明。

**运行中**：按钮文字变成「停止往复」，同时相对运动 / 绝对运动 / 设当前位置三个键被禁用，避免打断状态机。
点「停止往复」发的是 `0x0416` 相对 0 位移（目标 = 当前位置），电机停在原地并保持使能。
断开串口会把状态机重置回空闲。

E 行右侧的提示文字空闲时显示「`0° → 360° → 0° ×1`」（用的是输入框里的原始角度，不是协议量化回来的值，
所以不会显示成 359.82°），运行中显示「去程/回零 · 已完成次数 · 当前目标角度」。

### 面板收起（给曲线让位置）

曲线正上方那行有「显示面板」三个勾选框和一个切换按钮：

| 控件                   | 作用                                                         |
| ---------------------- | ------------------------------------------------------------ |
| 电机初始化（勾选框）   | 收起「电机初始化」整块面板                                   |
| 运动控制（勾选框）     | 收起「电机运动控制」整块面板                                 |
| 传感器寄存器（勾选框） | 收起底部寄存器表格                                           |
| 全部隐藏 / 显示全部    | 三块一起切换；全显时按钮文字是「全部隐藏」，否则「显示全部」 |

三块面板都放在 `Height="Auto"` 的网格行里，`Collapsed` 后行高自动变 0，
曲线所在的 `Height="*"` 行自动吃掉释放出来的空间，不需要改任何行高，默认三者都是显示状态。

界面纵向顺序（自上而下）：工具栏 → 实时数值 → 曲线控制行（含面板显隐勾选框）→ 曲线 →
电机初始化 → 电机运动控制 → 传感器寄存器 → 状态栏。曲线放在中间而不是最底部，
是为了让它独占剩下的所有高度，同时又不用把电机面板挤到窗口最上方。

**报错不会因此丢失**：面板收起时，`LblMotorStatus` / `LblMoveStatus` 里的红字会自动
镜像到底部状态栏（`LblMotorStatus` 对应 `_motorErrorText`，运动面板对应 `_moveErrorText`），
面板重新显示后状态栏里的镜像会自动消失，避免「面板关了就静默失败」。

### 录制 CSV 的电机列

点「开始录制」后，每收到一帧陀螺仪 `0x201` 就写一行，前 8 列是陀螺仪数据，
后面追加 5 个电机列：

| 列               | 含义                                                                    | 空值条件            |
| ---------------- | ----------------------------------------------------------------------- | ------------------- |
| `motor_deg`    | 电机角度（度），按写入该行时的轮径由 `motor_units` 换算               | 还没收到过位置回读  |
| `motor_units`  | 电机位置原始协议单位（0.1 mm 整数，来自 `0x0408/0x08` → `0x0409`） | 同上                |
| `motor_remain` | 剩余位移（`0x0420`，0.1 mm；0 即到位）                                | 还没收到 `0x0420` |
| `motor_torque` | 力矩（`0x0440`，s16）                                                 | 还没收到 `0x0440` |
| `motor_age_s`  | 该行距最近一次位置回读的时间差（秒）                                    | 还没有回读          |

**注意不是严格同步**：陀螺仪一行约 50 Hz，电机位置是 10 Hz 主动查询回读，所以同一份
读数会被连续多行复用，`motor_age_s` 最大约 0.1 s。要做严格对齐，用 `motor_age_s`
筛掉过期样本，或按 `motor_units` 变化点重采样。

**轮径中途改变时**：`motor_units` 是绝对量不受影响，`motor_deg` 按当行轮径换算，
所以角度序列会出现台阶（同一物理位置对应不同度数）。跨轮径分析请只用 `motor_units`。

> CSV 里没有电机数据时这几列**留空而不是写 0**，否则离线分析会把「没数据」当成「角度 = 0」。
> `StaticAnalyzer.Load` 按列名查找，因此新表头对旧的 8 列 CSV 仍然兼容。

## 三、协议速查

### 主控 → 电机

| 帧 ID      | 长度 | 内容                                                                          | 应答                         |
| ---------- | ---- | ----------------------------------------------------------------------------- | ---------------------------- |
| `0x0416` | 6    | 目标位置 s32(0.1mm) + **马达号** + 目标类型                             | `0x041A`                   |
| `0x0415` | 5    | 主速度 u32(0.1mm/s) + **马达号**                                        | `0x041A`                   |
| `0x0414` | 5    | 主加速度 u32(0.1mm/s²) + **马达号**                                    | `0x041A`                   |
| `0x0413` | 5    | `Data[0]` 0x5A=使能 / 0x4A=释放，`Data[4]`=**马达号**               | `0x041A`                   |
| `0x0408` | 2    | 设备号 + 子码：0x06 温度 / 0x08 位置 / 0x25 状态 / 0xFF 版本                  | `0x0409`                   |
| `0x0408` | 4    | 设备号 + 0x24 + 轮径(u16 LE, 0.01mm)，重复写 3 次                             | 实测回 `0x0409`            |
| `0x0316` | 8    | 电机参数初始化，`Byte6` 方向位 + **bit3..0 马达号**，`Byte7` 设备号 | 否                           |
| `0x0313` | 8    | 绑定 SN(7B) + 设备号                                                          | 否                           |
| `0x060D` | 2    | 主动查 SN（实测 `[00 00]` 及 `[01..04 00]` 均无应答）                     | 无；SN 只能靠上电 `0x0312` |

> 上表「马达号」「设备号」的区别见「设备号 vs 马达号」一节：协议原文把这几个运动帧的
> `Data[4]` 写作「设备号」，但实测只有填马达号才生效。

目标类型：`0x00` 相对（当前位置+Δ）/ `0x05` 绝对（坐标系里的坐标 P）/
`0x0A` 归零 / `0x0B` 设当前位置为给定值（电机不动，只改坐标系）。
从通道对应 `0x0419` / `0x0418` / `0x0417`（比主通道少一个目标类型字节）。
位移/速度/加速度均为**轮缘长度量**（0.1mm 系列），不是电机转角。

### 电机 → 主控

| 帧 ID             | 内容                                                                                                                                     |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `0x041A`        | ACK：`[原始帧ID 低2字节(LE), 马达号]`——末字节是**马达号**，不是设备号                                                          |
| `0x0409`        | 查询应答：`data[0:2]` 回显 dev+子码，`data[2:6]` 载荷（0x08 位置 s32 LE / 0x25 状态），`data[6:8]` 未确认                          |
| `0x0420+马达号` | 剩余位移：主通道 s32 + 从通道 s32（0.1mm），减到 0 即到位；绝对模式下为 `P − 当前位置`，可为负                                        |
| `0x0440+马达号` | 力矩：`Data[2..3]` s16                                                                                                                 |
| `0x0380+设备号` | 心跳（只有这一类的帧 ID 跟设备号）                                                                                                       |
| `0x0312`        | 上电 SN 上报（7 字节）                                                                                                                   |
| `0x0100~0x017F` | 错误码：0x0102 未到位 / 0x0104 堵转 / 0x0105 超温 / 0x0107 欠压 / 0x0108 断线；`0x0100 [34 12]` 实测为运动指令受理标记，不是缺轮径错误 |

### `0x0316` 参数表参考值

`B4 BF CF AA 00 5F` + `Byte6`(方向/往返解锁/自动返回/**马达号 bit3..0**) + `Byte7`(设备号)

`Byte6` 的 bit5/bit4 = 自动返回剩余位移/力矩，**0 = 使能**。实测发完整 `0x0316`
（含 `Byte6=0x00`）之后，`0x0420`/`0x0440` 才开始持续上报；发 `0x0413 [4A]` 释放后
仍继续上报。这才是"反馈流开关"的正确位置，不是 `0x0413` 使能。

`Byte6` 的 bit3..0 是**马达号**，运动帧 `Data[4]` 按它匹配。两台电机必须填不同值，
详见「设备号 vs 马达号（2026-10-23 实测）」。

脚本的 `move`/`wheel` 直接收 mm、mm/s、mm/s²，内部自动换算（见「〇、完整控制流程」末尾的
单位表）。
